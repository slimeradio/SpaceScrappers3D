# SpaceScrappers3D

Рабочая область для создания качественных 3D-моделей всех блоков игры SpaceScrappers.

## Просмотрщик

Запустите `./serve.ps1` из корня и откройте [просмотрщик](http://127.0.0.1:8769/viewer.html). Альтернатива: `python serve.py`. Порт можно изменить: `./serve.ps1 --port 8770`. Нужен браузер с WebGL2; зависимости локальны.

Кнопка «Открыть GLB / blend…» и перетаскивание файла открывают произвольную модель вне каталога. GLB загружается напрямую; blend читается установленным Blender в отдельное представление просмотрщика без генерации GLB. Исходный файл не перезаписывается. После открытия доступны объекты модели, изоляция, материалы, покраска, анимации и экспорт glTF / GLB. Для возврата к каталогу выберите проект SS.

Для blend упакуйте внешние текстуры и связанные ресурсы в исходный файл перед загрузкой: браузер передаёт только выбранный файл. Процедурные шейдеры представлены базовыми PBR-параметрами glTF, без запекания. Встроенные Python-скрипты blend не запускаются. Лимит файла — 512 МБ, преобразования — 4 минуты. Blender определяется автоматически (PATH, Blender Foundation, установленный на этом компьютере Steam Blender); явный путь: `./serve.ps1 --blender "D:/путь/blender.exe"` или переменная `BLENDER_PATH`. После обновления serve.py перезапустите сервер.

Импорты сохраняются отдельно от исходников во временной папке Windows `SpaceScrappers3D-viewer-imports`; URL импорта можно перезагрузить, пока эта временная копия существует. Импорт не добавляет модель в каталог проекта и не переносит её в другой стиль.

- Выбор проекта, стиля, блока, самостоятельной детали и конкретного экземпляра; щелчок по модели выбирает экземпляр. «Изолировать» показывает только его геометрию, «Вписать» возвращает камеру к модели.
- WASD перемещают камеру относительно направления взгляда, Space — вверх, C — вниз, Shift ускоряет движение. Работают физические клавиши, включая русскую раскладку. Перетаскивание вращает вид, колесо меняет приближение. Во время ввода в полях клавиши камеры отключены; при потере фокуса движение останавливается.
- Цвет, свечение, шероховатость, металличность и цветовая текстура применяются ко всему блоку или выбранному экземпляру. Исходный материал восстанавливается отдельной кнопкой.
- Анимации берутся из описания сборки: запуск, пауза, остановка, перемотка и скорость. Детали без анимаций явно обозначены.
- Оформление сохраняется в браузере; JSON позволяет перенести его. glTF экспортирует текущую видимую модель, материалы и анимации. Исходные JSON моделей при этом не перезаписываются.

Оболочка находится в `viewer.html` и `Viewer/`, запуск сервера — в корне. `Viewer/catalog.json` содержит явные ссылки на подключённые сборки, материалы и каталоги текстур. Подключены CHT-T01 / CorporateHiTech, CM-T01 / ChunkyModular и MA-T01 / MilitaryArmor, включая самостоятельные детали. Default пока не содержит моделей. Данные моделей остаются внутри своего стиля; каталог не сканирует архивные версии и не переносит художественные решения между стилями.

Для параметрической модели запись содержит `id`, `title`, `style`, `assembly`, `materials`, `textures`. Для Blender-модели — `glb`, `assembly` и список `parts` с полями `id`, `metadata`, `glb`. Пути задаются от корня; проект и стиль берутся из ID вида `SS/Style/Block` или из полей `project`, `styleName`. Поддерживаются параметрическая схема CorporateHiTech и glTF/GLB с иерархией экземпляров и анимациями. Дополнительные блоки добавляются в этот каталог.

`Viewer/export_blender.py` создаёт производные GLB для просмотра из текущих Blender-исходников MilitaryArmor и деталей ChunkyModular, в `Exports/Viewer/` соответствующего стиля. Запуск: `blender --background --python Viewer/export_blender.py`. Скрипт не сохраняет исходные .blend. Основная сборка CM-T01 использует уже существующий GLB. Процедурные узлы Blender в MilitaryArmor не запекаются: glTF отображает базовые PBR-параметры, а не точное воспроизведение процедурного шейдера Blender. Встроенные карты ChunkyModular сохраняются, «Исходный материал» восстанавливает их.

Просмотрщик сохраняет UV из GLB и строит проекцию в единицах модели там, где UV отсутствуют. Общая библиотека производных цветовых карт находится в `SharedTextures/Preview/`; normal/packed DDS не интерпретируются. Свечение и параметры поверхности регулируются отдельно.

Модели строятся из переиспользуемых деталей и наборов деталей. Это позволяет собирать новые блоки, сохранять единый визуальный язык внутри стиля и улучшать общие элементы.

## Структура проектов

Каждый проект и каждый его стиль имеют собственный изолированный контекст:

```text
Projects/<ProjectName>/<Style>/
```

Модели, материалы, референсы и художественные решения принадлежат конкретной паре проекта и стиля. Перенос между ними выполняется только по прямому указанию пользователя. Общий каталог блоков SS находится в `Projects/SS/Catalog/` и доступен всем стилям SS; это исключение не объединяет их визуальные контексты.

## Редактируемая 3D-графика

Предпочтительный подход — геометрическое и параметрическое моделирование: объёмы, кривые, поверхности и управляемые размеры. Первоисточник модели — Python-скрипт сборки. Он задаёт форму, материалы, сборку и позволяет менять деталь повторно. `.blend` — локальное превью этого скрипта: его можно собрать заново, в Git он не хранится. Полигональные сетки и изображения для игры и просмотра — производные результаты.

SVG может использоваться для плоских профилей, но сам по себе не является форматом полноценной 3D-модели.

## Текущие модели и состояния MilitaryArmor

Просмотрщик получает локально собранные Blocks/<ID>/<ID>.blend MilitaryArmor через /api/catalog; вручную обновлять список этого стиля не требуется. При открытии читаются превью, управляющие свойства, драйверы материалов и Actions. Первоисточник этих данных — Python-скрипты стиля. Подготовленное представление хранится отдельно в Projects/SS/MilitaryArmor/Exports/ViewerStates/ и автоматически обновляется при изменении превью или описания состояний. GLB для этого не создаются.

Панель «Состояния блока» переключает применимые состояния и независимые параметры; «Анимации» воспроизводят переходы и рабочие циклы. Обычные объектные анимации открываемого .blend также читаются из его текущей сцены. Используются базовые PBR-настройки; произвольные схемы узлов Blender браузер не исполняет. Экспорт управляемой модели из браузера сохраняет текущую позу; контролы и анимации остаются в локальном превью `.blend`.

Проверки и описание: Projects/SS/MilitaryArmor/ViewerStates.md.

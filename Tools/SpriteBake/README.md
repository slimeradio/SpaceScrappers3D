# SpriteBake — Blender → PNG

Универсальное ядро запекания. Оно не содержит художественных правил стилей,
не запускает их авторские скрипты и не экспортирует GLB. Команды запекания
не читают Unity; `export` и `sync-definitions` получают игровой проект явно.
Все зависимости модели должны находиться внутри выбранной папки стиля.

## Запуск

Полный контракт точек, креплений, Definition и переносимых пакетов описан в
[BlockExport.md](BlockExport.md). Дополнительные команды: `metadata`, `export`,
`sync-definitions`. Они не устанавливают новый визуальный стиль в игру.

Нужны Blender 5.2 и Python 3.11+ с `numpy` и `Pillow`. На текущей машине доступны
Blender 5.2.2 и комплектный Python Codex. Инструмент ничего не устанавливает.
PowerShell-вход автоматически находит комплектный Python; другой задаётся через
`-PythonPath`. Blender задаётся через `-BlenderPath`/`BLENDER_PATH` или определяется
по PATH и стандартным папкам установки, включая локальный Steam Blender.

```powershell
./Tools/SpriteBake/SpriteBake.ps1 inspect -Project SS -Style MilitaryArmor -Blocks MA-A01,MA-T01,MA-E01
./Tools/SpriteBake/SpriteBake.ps1 validate -Project SS -Style MilitaryArmor -Blocks MA-A01,MA-T01,MA-E01
./Tools/SpriteBake/SpriteBake.ps1 bake -Project SS -Style MilitaryArmor -Blocks MA-A01,MA-T01,MA-E01 -Quality all
./Tools/SpriteBake/SpriteBake.ps1 preview -Project SS -Style MilitaryArmor -Blocks MA-T01 -Quality all
```

Без `-Blocks` выбираются все блоки профиля. `-Quality 128`, `256` или `all`.
`-Force` принудительно запекает выбранные блоки; обычно он не нужен.
`preview` восстанавливает диагностические превью из актуальных PNG без рендера.
Отсутствующие или устаревшие игровые карты требуют команды `bake`.

Команда `validate -WriteRoles` — отдельная операция авторинга: записывает `ss_role`
в материалы деталей с резервным копированием исходных байтов. Без этого флага
ни одна команда не пересохраняет исходники. Применение профильного сопоставления
при обычной сборке происходит только в памяти; отчёт показывает, хранятся ли роли
в самом исходнике. Свойство `ss_role` имеет приоритет перед сопоставлением по имени.

## Профиль стиля

Конфигурация: `Projects/<Project>/<Style>/SpriteBake/profile.json`.
Версия схемы — `SpriteBake.Profile/1`. Пример рабочей конфигурации находится в
MilitaryArmor, но другой стиль получает собственную конфигурацию и материалы.
Общий каталог SS доступен только проекту SS. Каталог служит проверкой ID и размеров,
его отсутствие игрового XML не запрещает запекание.

- `axes`: строго `+Z` вверх, `-Y` вперёд. В PNG вправо `+X`, вниз `+Y`.
- `material_roles`: явное сопоставление имён материалов четырём ролям. Числовые
  суффиксы дубликатов Blender `.001` разрешаются по базовому имени; цвета не анализируются.
- Общие настройки: `samples`, `threads`, `ao_samples`, `ao_distance_bu`,
  `padding_pixels`, `emission_max`, `max_image_size`.
- `device`: CPU (по умолчанию), OPTIX или CUDA. GPU-профиль явно требует доступное
  устройство соответствующего типа, без скрытого переключения качества/бэкенда.
  На машине без такого GPU измените настройку на CPU; параметры входят в ключ кэша.
- Для блока: `assembly`, `source`, `bu_per_cell`, `footprint_bu` в порядке
  `[minX,minY,maxX,maxY]`, `height_range_bu` в порядке `[minZ,maxZ]`.
- `layers`: стабильный `id`, `draw_order`, `rotates`, `pivot_bu` и список `instances`.
  Каждый экземпляр принадлежит ровно одному слою. Неподвижная геометрия не вырезает
  скрытые участки вращаемой и наоборот: каждый слой захватывается отдельно.
- `states`: обязательны `damage0`, `damage33`, `damage66`, `destroyed`.
  Авторское состояние задаёт `frame` и необязательные полные локальные `poses`
  узлов (`translation`, `rotation_euler_xyz` в радианах, `scale`).
  Временная замена задаётся как `alias` конкретного состояния и обязательный `reason`.
- `clips`: именованный клип содержит явный список авторских `frames` и `fps`;
  статическая временная замена — `alias` состояния и `reason`.
- `use_author_animation` по умолчанию выключен. Включается только для явно выбранных
  диапазонов клипов: загружает action узлов из исходника сборки. Демонстрационные
  движения не становятся игровыми клипами автоматически.

Сборка для запекания создаётся в памяти из `assembly.json` и актуальных `.blend`
деталей. Поддерживаются `nodes` и непосредственные экземпляры относительно корня;
локальные преобразования и внутренние родители деталей сохраняются. Это обновляет
только зависимые экземпляры в производной сборке; авторский `.blend` блока не перезаписывается.
`source` сборки входит в зависимости и используется для явно разрешённых actions.

В `part.json` требуется список `materials` с `id` и `surfaces` — точными именами
объектов Blender. Это отделяет геометрию детали от студийного пола, камер и света.
Материалы должны иметь один Principled BSDF. Переносятся Base Color для Fixed,
Metallic, Roughness, Alpha, связанный Normal/Bump и Emission Strength.
Произвольные многослойные BSDF, transmission и объёмные материалы не являются
частью данного PNG-контракта. Непакованные статические текстуры внутри стиля
учитываются как зависимости; последовательности/видео не поддерживаются.

## Выдаваемые изображения

```text
Exports/Sprites/
  128/<Block>/PNG/<StateOrClipFrame>/<Layer>/*.png
  128/<Block>/Previews/*.png
  128/<Block>/Reports/report.json
  256/<Block>/...
  Previews/<Block>-128-vs-256.png
  Diagnostics/<Run>/...
  ValidationCache/...
  SourceBackups/<SHA256>/<Part>.blend
```

`PNG/` содержит только шесть карт на слой и кадр. Алиасы имеют собственные PNG,
поэтому потребитель не обязан понимать диагностический JSON. Отчёт нужен для
последующей интеграции: общий холст/origin, масштаб, pivot, порядок слоёв,
кодировки, зависимости, хеши, клипы и список временных замен.

| Карта | Кодировка |
|---|---|
| albedo | RGBA8, RGB sRGB, A — покрытие; Color1/Color2/Emissive нейтральны |
| material-mask | RGBA8 linear, независимые каналы Color1/Color2/Emissive/Fixed |
| emission | RGBA16 linear, нейтральная интенсивность / emission_max; A — покрытие |
| normal | RGBA16 linear, RGB = normal(+X,-Y,+Z) × 0.5 + 0.5; A — покрытие |
| height | RGBA16 linear, RGB = (Z-minZ)/(maxZ-minZ); A — покрытие |
| surface | RGBA8 linear, RGB = metallic/roughness/AO; A — покрытие |

**Alpha material-mask — вес Fixed, не прозрачность изображения.** Сумма четырёх
каналов равна покрытию albedo; веса на границе сглажены. Для смешивания материалов
нужно делить веса на покрытие, а прозрачность брать только из albedo.
Остальные RGB записываются без premultiplied alpha. Нормали после сглаживания
нормализуются. Emission — скалярные данные, а не sRGB-цвет: цвет задаст потребитель.
Превышение диапазона height запрещает публикацию. `emission_max` должен вмещать
авторские значения; текущий профиль рассчитан на Blender strength до 4.

Холст общий для всех слоёв и всех экспортируемых кадров; он включает footprint,
выступы и защитный отступ. Масштаб определяется опорной областью, а не AABB модели.
Отдельные слои и кадры не обрезаются. В отчёте высоты приведены и в BU, и в клетках.
Направленный свет, солнечные тени и bloom отсутствуют; AO записывается отдельно.

Color1/Color2 — роли областей модели, а не выбранные материалы вроде шифера.
Фактура не запекается в их albedo. PNG и параметры холста позволяют будущему
потребителю накладывать фактуру в плоскости блока. Это не UV-развёртка всех 3D-граней.
Две PNG-пробы окраски используют процедурную демонстрационную фактуру; они не
являются игровым материалом, не требуют скачивания и не меняют исходники.

## Кэш и отказы

Ключ блока включает его настройки, общие настройки, файлы деталей и метаданных,
исходник сборки, внешние текстуры, разрешение, Blender и код инструмента.
Изменение другого блока не сбрасывает его кэш. Повреждённый/удалённый выходной PNG
делает кэш неактуальным. Успешный пропуск обозначается `CACHED`.

Проверка деталей предшествует сборке. Нулевые треугольники и нечисловые координаты
запрещены; открытые оболочки разрешены, nonmanifold-рёбра перечислены в диагностике.
Автоматическое исправление геометрии ядром не выполняется.

Публикация выполняется для каждого блока/разрешения через временную папку на том
же диске, после проверки карт, превью и повторной сверки входных хешей. Ошибка
останавливает команду с кодом 1; ранее опубликованные результаты сохраняются.
Публикация всего каталога не является одной транзакцией: уже завершённые блоки
остаются готовыми. Повторный запуск продолжает через кэш.

Одновременные команды одного стиля блокируются OS-lock. После аварийного завершения
возможны `.staging-*` с непубликовавшимся результатом. Если осталась `<Block>.previous`,
инструмент требует ручного восстановления: сохранить обе папки, проверить отчёты,
вернуть previous на место отсутствующего блока. Автоматически удалять резервные
копии исходников или неоднозначные остатки инструмент не будет.

## Проверки

```powershell
# В Python-окружении с numpy/Pillow:
python -m unittest discover -s Tools/SpriteBake/Tests -v
python Tools/SpriteBake/Tests/run_acceptance.py --blender D:/SteamLibrary/steamapps/common/Blender/blender.exe
python Tools/SpriteBake/Tests/run_pose_acceptance.py D:/SteamLibrary/steamapps/common/Blender/blender.exe
python Tools/SpriteBake/Tests/run_action_acceptance.py D:/SteamLibrary/steamapps/common/Blender/blender.exe
```

Второй сценарий создаёт изолированные синтетические Blender-детали, проверяет
четыре роли и численные карты, повторный запуск, раздельную инвалидацию блоков,
общую зависимость, повреждённый источник и восстановление превью. Рабочие исходники
MilitaryArmor и Unity он не меняет. Артефакты остаются в `Exports/Sprites/Acceptance/`.
Последние два сценария отдельно проверяют полупрозрачный Fixed, общий холст разных
поз и действительную выборку заданных кадров Blender action.

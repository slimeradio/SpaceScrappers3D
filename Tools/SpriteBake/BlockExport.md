# Полный экспорт блока и Definition

```powershell
./Tools/SpriteBake/SpriteBake.ps1 metadata -Project SS -Style MilitaryArmor
./Tools/SpriteBake/SpriteBake.ps1 sync-definitions -Project SS -Style MilitaryArmor -GameRoot 'D:/Codex/SpaceScrappers' -BackupRoot D:/Codex/SpaceScrappers/SpriteBake-DefinitionBackups
./Tools/SpriteBake/SpriteBake.ps1 export -Project SS -Style MilitaryArmor -GameRoot 'D:/Codex/SpaceScrappers' -Quality all
./Tools/SpriteBake/SpriteBake.ps1 verify-export -Project SS -Style MilitaryArmor -Quality all
```

## Метаданные

`metadata` проверяет детали и вычисляет семантику в Blender без повторного рендера.
`Exports/Sprites/Metadata/<ID>.json` содержит контракт `SpriteBake.BlockMetadata/1`:

- Полные исходные assembly/part metadata, материалы, эмиссию, анимационные описания,
  совместимость, ограничения, крепления и области. Неизвестные авторские поля сохраняются.
- Точки и матрицы узлов для каждого экспортируемого состояния и кадра клипа. Алиасы
  отмечены `alias_of`; статическая замена не становится авторской анимацией.
- Для точки сохраняются локальные данные, стабильный ID экземпляра/категории/точки,
  слой, матрица, положение в BU и клетках, нормализованные направления и up.
- `parent` определяет систему локальных координат. `node` — ссылка на вспомогательный
  маркер, а не дополнительное преобразование к уже указанному position. Родитель
  `part`/null означает корень экземпляра; именованный родитель проверяется в Blender.
- Области rectangle/polygon сохраняют размеры/вершины и local_pose; экспортируются
  матрицы и преобразованные вершины. Нормали используют inverse transpose.
- SHA-256 исходных зависимостей; изменение источника во время экспорта запрещает публикацию.

## Синхронизация игровых XML

`sync-definitions` изменяет геометрию выстрела: RotationPivot и ShootPosition
у оружейных блоков с существующим XML. Для MiningLaser переносит MuzzleX/MuzzleY
из единственного mining-beam-origin/mining-laser-emission. Точки берутся из damage0 модели, с учётом
иерархии. Позиция ShootPosition — смещение от pivot: X вправо, Y вперёд/вверх
физической 2D-плоскости. Высота и полные 3D-направления сохраняются в metadata.
MiningLaser использует координаты от верхнего левого угла footprint, как Size;
они могут быть отрицательными или выходить за размеры клетки. Это согласованное
расширение общего загрузчика Definitions; NaN/Infinity по-прежнему запрещены.
У неподвижной установки без вращаемого слоя сохраняется существующий pivot:
модельная точка выражается относительно него, её абсолютное положение точно
совпадает с экспортом. Такой вариант разрешён только при нулевых дуге и скорости.
Наклон ствола по Z проецируется на плоскость существующей игры; направление,
повёрнутое в сторону в этой плоскости, отклоняется как неподдерживаемое текущим XML.
Стволы и точки сопоставляются слева направо; при совпадающем X — по Y и ID.
Число стволов должно совпасть с числом muzzle/shoot/launch/continuous-emitter.
Все точки обязаны принадлежать вращаемому оружейному слою. Расхождение
останавливает весь план до записи файлов, а не уменьшает число стволов.

Общие Turret/Weapon/Barrel выделяются в определения конкретного потребителя
со стабильным ID и собственной .meta, чтобы сохранить поведение остальных блоков.
Исходные байты XML сохраняются в указанной резервной папке; BOM, комментарии и
переводы строк вне изменяемых атрибутов остаются прежними. Повторная синхронизация
без изменений даёт ноль правок. У блоков без Definition сохраняется явный статус,
механика и баланс не придумываются. Остальные игровые параметры не меняются.

## Переносимый пакет

`export` публикует `Exports/Packages/<128|256>/package.json` версии
`SpriteBake.BlockPackage/1` и связанные файлы. В пакете находятся все PNG без
изменения битности/цветового пространства, model.json, images.json и байтовые
снимки связанных Block/Turret/Weapon/Barrel в DefinitionSources. Снимки Definition
сохраняют исходные ссылки и служат данными для будущей установки; они не являются
самостоятельным игровым каталогом с исходными текстурами старого стиля.

Манифест содержит SHA-256 каждого файла и списки: модели без Definition, игровые
Definition без модели, ID общего каталога без модели и сборки без профиля. Перед
копированием сверяются хеши карт и их источников, размеры footprint, слои, кадры
и клипы. Ранее запечённые PNG можно упаковывать без нового рендера, если их исходники
и перечисленные параметры неизменны; исходная версия производителя остаётся в отчёте.
Пакет публикуется целиком через staging; неудачный экспорт сохраняет прежний пакет.
`verify-export` независимо перечитывает каждый файл, проверяет SHA-256 JSON/XML/PNG,
соответствие ID и кадров, а также шесть карт на каждый слой каждого кадра.

Выбор блоков задаётся `-Blocks`, разрешения — `-Quality`. Полный экспорт без
`-Blocks` включает все модели профиля. Отсутствующие модели не создаются из CSV:
они перечисляются в coverage. Редактируемые .blend остаются в библиотеке деталей,
GLB не генерируются. В пакет входят данные и изображения; установка стиля, новый
игровой шейдер и управление палитрой выполняются отдельно по решению пользователя
2026-10-16. Пакет явно обозначает `runtime_format: requires-game-import`.

Полная команда `export` отказывает, если в Blocks найдена сборка без настроек
профиля. В MilitaryArmor новые модели регистрируются командой
`python Projects/SS/MilitaryArmor/SpriteBake/prepare_profile.py --append-missing`.
Она добавляет только отсутствующие ID, сохраняя все ранее настроенные блоки.
Затем запекаются только новые ID через `bake -Blocks ...`.

Добавление роли для нового материала не требует перепекать другие блоки,
если этот материал отсутствует во всех их разрешённых `material_slots`.
`image_settings_match` допускает только добавление неиспользуемых имён:
изменение/удаление прежней роли, добавление используемой роли, любой другой
параметр и хеш исходника остаются строгими. Первоначальный отчёт производителя
и его параметры сохраняются без переписывания. Для обновлённых MA-H01..MA-H03
с разделёнными левыми/правыми рёбрами выполнено отдельное запекание обоих
качеств; Thermal сохраняется как Fixed в холодном авторском состоянии.

При полной игровой интеграции SS-0109 после этих трёх радиаторов повторно
запечены остальные 52 модели с изменёнными исходниками, в обоих качествах.
Игнорирование изменённых assembly/blend по семантическому сходству не
поддерживается: каждый хеш `images.inputs` должен совпадать с текущим файлом.
Девять моделей с неизменными исходниками переупакованы без рендера. Все 64
модели имеют игровые Definition; снимки Definition обновляются при экспорте.

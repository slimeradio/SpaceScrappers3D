# Сделай хорошо

Работай из корня этого репозитория. Прочитай AGENTS.md, README.md и инструкции только выбранного Projects/<ProjectName>/<Style>/. Если проект или стиль не определён контекстом, уточни его до чтения моделей. Общие данные SS доступны в Projects/SS/README.md и Projects/SS/Catalog/.

## Подготовка

Проверь Git, Git LFS, Python и Blender. На новом Windows-компьютере запусти ./setup.ps1 -InstallMissing; учётные данные GitHub и имя/email коммитов принадлежат текущему пользователю. Не копируй личные пути или учётные данные автора проекта. Путь Blender можно задать BLENDER_PATH. После установки проверь реальные версии и работоспособность инструментов.

До изменений проверь git status --short и запомни чужие изменения. Не включай их в свой коммит. При пересечении чужих правок с нужным файлом согласуй совместное изменение до коммита.

## Модель

Определи назначение, габариты, единицы, оси и визуальный язык по текущему стилю. Первоисточник модели — Python-скрипт сборки. Меняй его. Текстуры храни по переносимым относительным путям. Не создавай GLB без нового прямого запроса пользователя.

Создавай переиспользуемые детали в Parts/<PartId>/, затем сборки в Blocks/<BlockId>/ по существующей структуре стиля. Сначала проверь каждую новую или изменённую деталь: размеры, нормали, вырожденную геометрию, пересечения, крепления и материалы. Замкнутость проверяй там, где поверхность должна быть замкнутой. После проверки обнови только её экземпляры в затронутых сборках.

Собери локальное превью `.blend` тем же Python-скриптом. Проверь сборку, зазоры и крайние позы анимаций. Повторно открой это превью в Blender, проверь наличие текстур и сделай предпросмотр характерных ракурсов. Исправь найденные дефекты в Python и пересобери превью. Сохрани описание и результаты проверки рядом с моделью. Не выдавай проверку Blender за проверку в игре. Текст сохраняй с CRLF. `.blend` и каталог `.generated` в Git не добавляй.

## Завершение и Git

Успешно завершённую задачу автоматически сохраняй коммитом: пользователь этого проекта разрешил коммит результата навыка. До коммита проверь git diff, git diff --check и список файлов; добавляй через git add -- только явно перечисленные файлы своей задачи, включая исходники, нужные текстуры, метаданные и доказательства проверки. Проверь git diff --cached --stat и git diff --cached --name-only; при чужих staged-изменениях не включай их в свой коммит и не сбрасывай их.

Git LFS должен быть установлен до добавления бинарных ресурсов, которые остаются в репозитории. Не подменяй отсутствующие LFS-объекты указателями. Не коммить секреты, кэши, `.blend`, резервные `.blend1` и `.generated`. Коммит должен описывать созданную модель и её назначение и содержать Python-первоисточник. Не коммить незавершённую модель как готовую при проваленной проверке; сообщи причину.

В ответе укажи Python-исходник, локальное превью, выполненные проверки и хеш коммита. Коммит локален; отправляй его в удалённый репозиторий только по прямому запросу пользователя. Для общего репозитория другу нужны собственные права на запись либо fork.

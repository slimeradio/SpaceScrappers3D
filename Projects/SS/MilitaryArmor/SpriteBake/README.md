# MilitaryArmor — профиль запекания в PNG

Пайплайн: [общий CLI и контракт](../../../../Tools/SpriteBake/README.md).
Относительный путь выше ведёт к общему инструменту этого workspace; визуальные
данные других стилей не используются.

`profile.json` явно подключает 64 текущие сборки и их детали. Игровые определения
не создаются командой bake. В отчёте каждого блока приводится состояние его ID
из общего каталога SS, включая визуальные заготовки без игрового XML.

`metadata` экспортирует функциональные точки и крепления по кадрам, `export`
собирает переносимый пакет, `sync-definitions` обновляет точки выстрела и pivot
в существующих игровых XML с резервным копированием. Согласовано 2026-10-16:
источник координат — модель; модели без Definition экспортируются с отметкой.
Установка нового стиля и расширение игрового рендера выполняются отдельно.
См. `Tools/SpriteBake/BlockExport.md` от корня workspace.

## Материалы в исходниках деталей

Материал назначается граням детали обычным способом в Blender. В Custom Properties
материала находится строка `ss_role`, принимающая строго одно из значений:

| Исходный материал | Роль |
|---|---|
| Ceramic | Color1 |
| Armor | Color2 |
| Signal, Optic | Emissive |
| Titanium, Steel, Dark, Mark, Warning, Photovoltaic | Fixed |

Это начальная явная разметка текущего набора. Художник может назначить другую роль
в конкретном исходнике детали: существующий `ss_role` имеет приоритет над таблицей.
У экземпляров одной детали назначения сохраняются при каждой производной сборке.
Создавать отдельные материалы на каждом блоке не требуется.

Для новых материалов задайте `ss_role` в исходнике. Для новых создаваемых из старых
авторских скриптов деталей, которые ещё не содержат свойства, используйте явную
миграцию `validate -WriteRoles` после проверки геометрии. Старые скрипты моделирования
не запускаются пайплайном: некоторые из них исторически экспортируют GLB.

## Масштаб и слои

Для MA-T01 задано 2.4 BU на клетку: опорная ширина старой модели 4.8 BU соответствует
двум клеткам. Footprint — 2×3 клетки, центр в (0,0). Это явное решение профиля,
а не изменение геометрии или физического масштаба Blender-источника.
Для остальных текущих сборок задан 1 BU на клетку с footprint по catalog_grid.
Соответствие силуэта и посадки требует художественной проверки по grid-превью.
Текущий профиль использует Cycles OPTIX, 16 samples и 8 AO samples. На текущей
машине доступна RTX 3050 Laptop GPU. Для машины без OptiX выберите device=CPU
в профиле; разрешение и число выборок при этом сохраняются.

MA-T01 и MA-W01…MA-W06 разделены на неподвижное основание и вращаемую башню по
явным узлам их rig: Azimuth или Yaw. Все остальные блоки пока имеют один слой body.
Направление -Y находится сверху изображения; поворот демонстрационной сцены
игнорируется, используется исходная поза из assembly.json и актуальные детали.

Диапазоны высот заданы отдельно для каждого блока с запасом относительно текущих
авторских габаритов. При изменении геометрии, выходящем за диапазон, обновите профиль;
автоматически менять масштаб высот между кадрами запрещено.

## Состояния и пилот

Пилот — MA-A01, MA-T01, MA-E01, профили 128 и 256 px/cell.
Пока утверждённые повреждения и рабочие игровые клипы отсутствуют:

- damage33, damage66, destroyed используют явно отмеченные копии damage0;
- fire оружия и work экспортных модулей MA-E* имеют статические замены;
- полный оборот и наклон башни из демонстрации не становятся игровыми анимациями.

Точный список замен находится в `temporary_replacements` отчёта каждого результата.
PNG `destroyed` сейчас также является временной копией целой модели. Этот пакет
не означает готовность повреждений, уничтожения, рабочих эффектов или интеграции в игру.

```powershell
./Tools/SpriteBake/SpriteBake.ps1 bake -Project SS -Style MilitaryArmor -Blocks MA-A01,MA-T01,MA-E01 -Quality all
# Все подключённые готовые модели:
./Tools/SpriteBake/SpriteBake.ps1 bake -Project SS -Style MilitaryArmor -Quality all
```

Выходные карты находятся в `Exports/Sprites/<128|256>/<Block>/PNG/` относительно
корня стиля. Диагностические превью и отчёты лежат отдельно от этих PNG.

## Исправления исходников перед запеканием

У части прежних деталей bevel создавал совпадающие вершины и нулевые грани.
`repair_bevels.py` использован только для деталей активных сборок: добавляет Weld
после bevel и перед Weighted Normal, не применяя модификаторы и не меняя базовую
сетку. После исправления каждая изменённая деталь повторно проверена.
Список деталей/объектов и исходные SHA-256 — `bevel-repairs.json`; байтовые резервные
копии находятся в Exports/Sprites/SourceBackups. Скрипт не является частью обычного bake.

`prepare_profile.py` сохраняет рецепт первоначальной конфигурации. Без флага он
отказывается перезаписывать существующий профиль. `--append-missing` регистрирует
только новые сборки, сохраняя ручные настройки всех существующих ID. MA-W07…MA-W12
подключены этим способом; прежние 58 блоков не менялись и не пересобирались.

Техническая проверка PNG не заменяет художественную приёмку. Unity не запускается;
новый стиль не устанавливается. Только явно вызванный `sync-definitions` меняет
связанные игровые XML по согласованным координатам модели.

После сборки `verify_delivery.py` повторно сверяет входные хеши, актуальность кода
и настроек, все выходные PNG и их количество. Он сохраняет
`delivery-verification.json`, сводный пилот `Exports/Sprites/Previews/pilot.png`
и уменьшенный обзор каталога `Exports/Sprites/Previews/catalog-overview.png`.
Модели в обзоре масштабируются в одинаковые рамки; физический размер проверяйте
по отдельным grid-превью, где сохраняется число пикселей на клетку.

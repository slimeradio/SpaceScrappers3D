# Правила рабочей области

- Все текстовые файлы сохранять с переводами строк CRLF.
- Новые строки MySpaceTexts и .resx добавлять в конец соответствующих списков ресурсов.
- Контекст работы ограничен выбранной парой `Projects/<ProjectName>/<Style>/`.
- Не читать и не использовать материалы, модели, референсы и решения других проектов или стилей без прямого указания пользователя. Не изменять их в рамках текущей задачи.
- Общие правила корня действуют для всех проектов. Сведения о моделях, художественном направлении и производстве хранить внутри соответствующего проекта и стиля.
- При работе в `Projects/SS/Default/` не переносить автоматически правила, инструменты и художественные решения из репозитория игры SpaceScrappers или прежних проектов. Подключение внешнего контекста требует прямого указания пользователя.
- Первоисточник модели — Python-скрипт, который её создаёт. `.blend` — локальное превью: тот же скрипт собирает его заново, в Git его не передавать. Производные экспорты хранить отдельно от Python-исходников.

- Исключение для общих данных проекта SS: Projects/SS/README.md и Projects/SS/Catalog/ доступны всем его стилям. Каталог блоков хранить и обновлять централизованно; визуальные контексты стилей остаются изолированными.
## Создание и обновление моделей

- GLB (в сообщении пользователя также «GBL») больше не генерировать без нового прямого указания пользователя. `.blend` собирать локально из Python и не добавлять в Git. Существующие экспорты автоматически не удалять.
- При правках менять Python изменённой детали, пересобрать её превью, затем обновлять её экземпляры в затронутых сборках. Не выполнять полную пересборку неизменённых деталей и блоков.
- Проверять геометрию каждой новой или изменённой детали сразу, до её включения или обновления в сборке блока. Ошибки исправлять на уровне детали до зависимых этапов.

## Переносимая работа и коммиты

- Для просьбы «сделай хорошо» использовать .agents/skills/sdelai-horosho/SKILL.md. Навык поставляется вместе с проектом.
- Завершённый и проверенный результат этого навыка сохранять локальным коммитом, включая только файлы текущей задачи. Чужие изменения сохранять. Push выполняется по отдельному запросу.
- Подготовка нового компьютера описана в GETTING_STARTED.md; пути и учётные данные текущего компьютера не переносить другу.
